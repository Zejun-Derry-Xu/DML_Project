## 用户会遇到什么

选中本人订单和商品后，程序核验送达、期限、final sale、重复退货，并同时展示四项
不应出现的问题：衣服污渍、衣服破损、原吊牌剪掉/脱落、吊牌损坏。没有预选答案。
退货原因现在对清单主流程可选；用户提供的原因仍保留原文。

- “上述问题都没有，并提交退货”：对当前清单作整体声明并授权提交，通过最终复查后
  一步创建模拟 RMA，不再要求逐项回答或再次确认。
- “都符合”：只完成条件声明，之后只需提交确认。模糊的“嗯/可以/yes/okay”不算整体授权。
- “不确定”：先问哪一项有疑问，不把四项全部填成未知。只围绕例外继续澄清。
- “吊牌剪掉了，可以退吗”：在主对话里引用当前案件政策，优先问成因；到货已有/原因未知
  转模拟人工，顾客造成的状态问题按政策拒退，不再追问无关条件。
- “吊牌脏了”：现有政策未定义单独的吊牌清洁标准，不能发明拒退规则；实际异常转模拟人工。
  假设性咨询只解释政策，不替用户填写商品状态或创建工单。

本项目仍是基于顾客陈述的模拟预审，不是实物验货，也不转账。

## 关键实现

`app/services/checklist_service.py` 是独立的清单对话控制器，复用现有订单检查、事实合并、
最终复查和原子 RMA 创建。`COLLECTION_STYLE=checklist` 为新默认；`conversational` 和
`individual` 保留为历史收集模式，不作为新主流程。原因可选的产品路径是 checklist。

清单不是一个“全部良好”布尔开关。服务器把四个条件及期望值保存为快照，绑定 question_id、
案件版本、商品、订单和案件政策版本。整体声明有单独来源 `user_attestation`，保存用户原句、
快照及此前事实；它不能覆盖已有异常或冲突。按钮表达明确声明与提交含义，在模型关闭时也能用。

自然语言由现有模型的一次调用同时提供具体事实、整体回应、提交意图、政策问题与证据。
新说明包为 `app/extractors/specs/apparel-checklist-v2.md`，提取契约版本 `apparel-extraction-2.0.0`。
不新增模型或用于生成追问/解释的调用。明确异常和未知优先于概括性声明。

政策解释复用现有 `LexicalPolicyRetriever`，从案件绑定版本的语料中找条款并原文引用。
没有新增向量库，也不声称使用了向量 RAG。纯政策问题不消耗澄清次数，不替换当前清单；
有具体事实则先记录并解释，再推进流程。程序依旧控制资格判断。

两次针对性澄清没有进展后生成模拟工单，包括成因追问；明确某一项不知道算信息进展，
不是回答失败。模型不可用时不消耗失败次数，显示限制并保留清单的明确按钮。

## 接口与兼容

- `QuestionResponse.checklist_items`：服务器生成的条件字段、问题描述及期望值。
- `ChatRequest.in_reply_to_question_id`：可选新增字段；自然语言整体声明/提交必须引用当前问题。
  前端自动携带。未关联、旧问题、过期或错误商品范围不能提交。
- 现有问题回答接口新增 `attest_and_submit`、`uncertain`、`cancel` 选项值。
  单项问题和已有确认卡继续兼容，不新增退款接口。
- `/ready` 新增 `collection_style`；冒烟脚本识别新的清单问题。
- 不增加数据库列。旧未完成案件进入清单模式时保留事实、替换旧收集问题；已完成案件不改。
  升级须部署匹配的 API/前端镜像，不能混用旧前端的按钮语义。

事务末尾仍复查资格。文本声明和按钮提交共用现有原子商品占用及幂等约束；
请求处理期间过期也不能提交。重复提交不产生第二个模拟 RMA。

## 本轮验证与边界

自动化 API 测试使用隔离 SQLite 和模拟 Ollama HTTP 响应，经过真实请求解码、证据验证及
事务路径，不是跳过校验的预置业务答案。覆盖整体声明/提交分离、过期和错误作用域、
异常优先、政策只读插话、未知与成因追问停止、降级按钮、重复请求、归属隔离及历史恢复。

浏览器使用独立临时 SQLite 和同样明确标记的模拟 Ollama 服务验证实际界面。
这些只能证明交互协议走通，不是 Qwen 准确率、延迟或真人效率结果。
PostgreSQL 实测、真实 Qwen 自然语言验收、真人试用和云端升级仍未完成。

本轮不运行大规模模型评测，不启动本地 Docker，不恢复或修改 Jetstream2。
现有未跟踪数据和用户评测改动保持原状。政策仍为 `apparel-1.0.0`，未扩大政策判断标准。

本地记录：完整后端测试 **390 项通过**（清单 HTTP 测试 28 项），前端规则测试 **6 项通过**；
Ruff、mypy（84 个源文件）、前端 lint 和生产构建通过。既有 Starlette/httpx 弃用警告仍在。
只读 `smoke_apparel` 在隔离服务上通过 health、ready、政策期限引用 **3 项检查**；
没有把按钮流程或测试替身标记为真实模型传输/质量验收。浏览器在临时数据库中创建了
一个模拟 RMA，并验证另一案件的剪牌政策引用和仅追问成因；没有真实退款或外部通知。
条件说明区独立于聊天滚动区，避免自动滚动把清单前几项遮住。
本轮代码保持本地未推送状态，未运行新的 GitHub CI，也未部署。
